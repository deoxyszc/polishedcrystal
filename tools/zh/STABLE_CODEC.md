# 稳定汉字编码：分阶段工作流程

## 目标与边界

本方案不是从源码到编码表的全自动工具链，而是带人工审核环节的分阶段流程：

源码扫描（辅助证据） → 人工审核并维护控制码清单（权威输入） → 自动生成编码表 → 检查变更报告。

扫描器不能保证理解任意汇编写法。未扫描到某个字节的使用，不代表该字节可分配。自动化负责确定性分配和校验，不代替控制码语义审核。

## 各阶段的职责

1. 扫描源码：提取控制码声明、分派表、文本宏参数及相关字符串读取位置，输出供人工核对的证据。不能直接把扫描结果当成批准的编码空间。
2. 人工维护权威清单：区分外层文本脚本、原版字符串、中文私有流；记录字节值、作用域、参数长度或变长规则、终止行为、首字节和尾字节限制、源码依据。原版英文字符、动态插入、压缩入口及旧逐字节扫描也必须考虑。
3. 自动分配：读取审核后的清单、完整 GB2312 汉字集合和可选旧表。首次无旧表时确定性生成；后续锁定全部仍合法的旧映射，只迁移冲突项。控制码删除不主动重排。容量不足、重复编码或旧表损坏时报错。
4. 检查结果：核对控制码增删、映射变化、可用容量及输入版本。采用的清单与编码表应一起纳入版本管理；运行时接入前另行检查解码器和消费者。

## 什么时候需要人工更新

新增、删除或修改文本控制码，改变其参数、终止行为、解析入口，或增加影响首尾字节合法性的字符串读取规则时，需要重新审核权威清单。普通无关源码改动不应触发审核。扫描发现与清单不一致时，应检查并更新清单，不能静默修改权威输入。

清单应有明确版本；编码输出应记录清单哈希、分配算法版本、旧表哈希及映射哈希。同一组输入必须产生相同映射。没有旧表也可以生成，但不承诺保留历史分配。

## 第一版已完成

权威输入为 control_codes.json（版本 1，由 AI 根据当前源码审核）。生成器不依赖源码哈希锁，不会因无关源码变化拒绝生成。审核可由人或 AI 执行，必须核对文本语义和首尾字节约束，不是机械接受扫描结果。

第一版产物保存在 codec-v1/：encoding.json 是 6763 个 GB2312 汉字的双字节编码表；controls.json 是生成时的审核清单快照；changes.json 记录输入哈希与容量。可用编码对 13640 个，余量 6877 个。当前旧读取路径要求在尾字节中额外排除空格与两个性别字符。

首次生成：

```bash
python3 tools/zh/stable_codec.py --controls tools/zh/control_codes.json --output tools/zh/codec-v1
```

更新清单后增量生成（保留旧版目录）：

```bash
python3 tools/zh/stable_codec.py --controls tools/zh/control_codes.json --previous tools/zh/codec-v1/encoding.json --output local-data/encoding-next
```

辅助扫描，独立输出差异，绝不修改权威输入：

```bash
python3 tools/zh/control_scan.py --output local-data/encoding-generated/scan-diff.json
```

扫描差异为空不等于所有运行路径通过验证。新增内联解析方式仍需审核。首版编码表完成不代表运行时接入完成。

## 运行时接入与资源限制

中文构建将完整纯汉字段落编译为稳定双字节码，运行时查稀疏目录，再将12px字形的三个分片配对送入公共缓存。首字节判定由实际目录生成，不写死编码范围。混合 Latin、空格及标点的段落已进入同一分片配对循环；GB2312 Han 使用稳定双字节码，其他已加载标点使用现有 E1 转义。菜单、名字、输入和存档尚未迁移。

临时组合复用现有12字节 wZhNameBuffer，仅在同步纯汉字段落期间使用，不与动态名字 staging 并发。目录当前每字10字节加结束符与首字节判定代码，在现有语言 bank 内链接，不新增 bank 或扩大缓存。较大字库仍需核算同bank容量。生成成功和局部画面通过不等于所有游戏路径兼容。

## 旧绘制协议移除

0E 分片绘制指令及其解释器、生成函数、旧测试夹具已移除。Start、战斗指令、操作菜单、招式、队伍提示均生成字符流；菜单使用现有0A入口的有界描述符（样式及长度），不是逐图块指令。原版英文 PlaceString 路径保留。第一版 codec-v1 中的清单为历史输入快照，其中旧0E声明不表示当前运行时仍支持；当前权威清单版本2将0E列为退役保留字节，不重排旧映射。

队伍和HUD共享名字记录与去重元数据，旧英文名引用原表；不扩充名字或存档字段。357字形、292名字全量本地构建已链接，实际菜单与名字显示属于局部验证，不代表所有模式回归。

## 当前验收范围与后续检查

当前按基本功能可用验收：正常文本显示、菜单进入与返回、名字显示、正常混合文本和构建成功。详细边界验证暂不作为本轮合并阻塞，不把未测情况描述为已通过。

后续细化：空串/截断/未知码与长度不一致；奇数汉字与动态名字/控制符衔接；菜单逐项终止符扫描；跨bank恢复及临时区生命周期；最长名字、满菜单与缓存不足的失败行为。已有局部CPU和画面验证不能替代这些完整检查。
