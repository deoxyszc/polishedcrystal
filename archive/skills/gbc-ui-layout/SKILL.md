# GBC 中文界面排版

动手前先用简短中文说明观察到的问题、拟改的区域和验证范围；已有授权内直接推进，无须为普通改动再请求确认。

## 资源预算：最高优先级前提
GBC资源（ROM、内存/WRAM、显存/VRAM）寸土寸金，禁止任何未经用户明确批准的扩容。不得自行增大ROM容量、缓存池、缓冲区、窗口栈、名字/存档字段，或新增/借用bank来绕过容量问题。首先在既定预算内优化编码、去重、复用和生命周期；确实无法解决时，报告实测占用、所需增量、原因及替代方案，取得用户明确批准后才能实施。历史新增分配不构成今后扩容授权，也不得把物理容量尚有空闲当作授权。

## 确认基线
先读当前仓库交接与踩坑记录。历史截图要与对应源码核对，区分早期候选、用户定稿和已撤销实现；不得凭文件名或时间独自认定定稿。沿用已确认的对齐关系，不以旧截图覆盖新选择。页面布局独立配置；旧预合成实现只作布局意图参考。

## 实施与检查
用户要求看实际效果时，直接在隔离 ROM 实现并运行；不以叠图代替。构建与存档操作沿用 gbc-rom-build-debug 技能。冷备先复制，使用只读输入/工作副本，测试不保存；RAM夹具必须说明改了昵称、物种还是状态，不能只改名就宣称测试了真实物种。

提交截图前由 subagent 查看完整画面和必要的整数倍最近邻放大图，逐项确认：
- 文字：完整字形、最后一行与底边间距、行距、基线；菜单应按中文实际宽度衡量，避免沿用英文空白宽度。
- 光标：与12px字形视觉居中，每项切换后旧箭头消失；双图块光标必须清理两格及属性。
- 边框与背景：上下左右留白协调，子菜单遮挡父提示是否符合预期；不要将截断提示或贴边字交给用户发现。
- 精灵和图标：检查名字墨迹之外的白底和ClearBox清屏矩形，不可擦掉立绘；核对性别、状态、血条、经验条、捕获和闪光位置及调色板。
- 数据与状态：用当前授权范围内的长短名字、等级或状态作有意义的边界检查，保留真实HP/PP机制；超出范围未测的项目列明，不扩大回归任务。
- 动作：进入、切换每个菜单选项、取消、返回父页面后重画；两层菜单的tilemap和attrmap必须同步，不只看WRAM正确就推断屏幕正确。

## 诊断与交付
先定位像素对应的tilemap、属性、清屏矩形或资源写入，再解释原因。4px字形补白、8px图块取整、清屏留白是不同来源，不能猜测互相替代。局部修复尽量沿实际调用入口，撤销未奏效的诊断改动，重建并验图。

每张中文效果图配同场景英文完整参照；截图文件与当前ROM/hash对应，不覆写后仍称旧图。明显排版错误先修再交付；有阻塞时呈现失败证据与边界，不称已通过。验收结论区分编译、画面、导航、游戏机制和全流程。记录当前布局坐标、独立配置、验证范围和用户暂缓项，唯一交接入口指向最新证据。

已定稿页面的中文文本在用户授权范围内提交；ROM、字体、存档与本地截图不自动随之公开。修改PR不等于授权合并。

## 图片读取与报告（用户明确要求）

主 agent 禁止直接读图，所有图片读取和视觉分析先委派给 subagent。subagent 只返回文字结论、问题位置及图片路径，不向主对话回传图片。仅当 subagent 发现问题并反馈后，主 agent 才可读取相关图片核查。此授权限于读图分析，不扩展其他委派范围。

最终报告仍须用绝对路径 Markdown 图片嵌入实际效果图供用户查看，中文效果配同场景英文完整参照；展示文件不要求主 agent 先读取图片。避免主对话累积图片导致请求失败。

每次验图必须新建 subagent，以 fork_turns=none 使用空白上下文，只传必要文字背景和图片路径；不得向已读图的旧 subagent 继续追加图片。仅当工具明确支持且确认清空该 agent 全部历史上下文后才可复用；followup 新一轮消息、重置工具会话均不等于清空 agent 上下文。单批图片保持精简，大批次拆给不同新 agent，避免任何会话累积接近50张。

读图 subagent 使用用户指定的 gpt-5.6-sol。创建时显式设置 model=gpt-5.6-sol 与 fork_turns=none，不继承主 agent 的 GPT-6 模型。
